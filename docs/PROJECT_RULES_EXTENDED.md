# PROJECT RULES (Extended)

## 1. Цели и принципы

> **Дата создания:** 2026-02-09  
> **Последнее обновление:** 2026-02-17  
> **Статус:** ✅ Актуально

- **Надёжность**: отказоустойчивость при нестабильных внешних источниках.
- **Безопасность**: строгий allowlist, запрет SSRF, безопасные заголовки.
- **Поддерживаемость**: модульность, низкая связность, чистая архитектура.
- **Наблюдаемость**: структурированные логи, метрики, корреляция запросов.
- **Детерминизм**: зафиксированные версии зависимостей.

## 2. Структура и архитектура

- **UI / Domain / Infra**: строгое разделение ответственности.
- `App.tsx` — только композиция и роутинг (цель < 300 строк).
- Все бизнес-операции — в `services/`.
- Все повторяемые UI-решения — в `components/ui`.
- Любая логика состояния — в `hooks/`.

## 3. Качество и тестирование

- Любой новый код сопровождается тестами (unit + integration).
- Любая критичная логика (прокси, парсинг, LLM) имеет фикстуры.
- Минимальные уровни покрытия:
  - `services/*`: 70%+ line/branch coverage.
  - `server/*`: 60%+ line coverage.

## 4. Безопасность

- Запрет приватных IP/localhost в прокси.
- Allowlist доменов для прокси (`rutube.ru`, `*.rutube.ru`).
- `cors` только с whitelist.
- Rate limit на `/api/proxy` и `/api/ai/*`.
- Валидация входных данных (Zod/Valibot).
- CSP, X-Frame-Options, X-Content-Type-Options.

## 5. Наблюдаемость

- Логи в JSON со следующими полями: `timestamp`, `level`, `requestId`, `module`, `message`, `context`.
- Единый `requestId` для backend + проброс на frontend.
- Метрики p50/p95/p99 для прокси/LLM.

## 6. Стандарты разработки

- Pre-commit hooks: lint + typecheck + tests.
- ESLint + Prettier обязательны.
- Запрещён `@ts-ignore`. Исключения — только с обоснованием и сроком.
- Никаких `alert/confirm` — использовать модальные компоненты.

## 7. Работа с документацией

- Обновлять `docs/ARCHITECTURE.md` и ADR при любых архитектурных изменениях.
- Вести `CHANGELOG.md` с датой и типом изменения.
- Всегда обновлять `docs/STATE_MANAGEMENT.md` при изменениях в сторе.

## 8. Производительность

- Виртуализация списка видео при > 200 элементов.
- `React.memo` + `useMemo` для тяжелых компонентов.
- Debounce на поиске (300–500мс).

## 9. AI/LLM

- Fallback логика обязательна, иначе запросы отклоняются.
- Кэширование LLM ответов с TTL.
- Валидация формы ответа.

## 10. Порядок внесения изменений

1. Обновить ADR при изменении архитектуры.
2. Реализовать код и тесты.
3. Добавить/обновить документацию.
4. Прогнать тесты и линтер.
5. Проверить безопасность прокси.
