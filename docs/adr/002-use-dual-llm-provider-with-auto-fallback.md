# ADR-002: Использование двойного провайдера LLM с авто-fallback

## Статус

Принято

## Дата

2026-02-09

## Контекст

Для реализации функции KinoRate AI (обогащение метаданных фильмов через искусственный интеллект) требуется надежный доступ к LLM. Однако использование одного провайдера LLM может привести к сбоям в работе при недоступности этого провайдера. Также важно минимизировать стоимость и максимизировать качество получаемых данных.

## Решение

Реализовать систему с двумя провайдерами LLM (Google Gemini и Mistral AI) с автоматическим fallback'ом:

1. **Сервер автоматически определяет доступных провайдеров** по наличию API-ключей в environment variables
2. **При ошибке одного провайдера** происходит прозрачный переход на другой
3. **Для Gemini используется JSON-схема** для снижения вероятности галлюцинаций
4. **Реализовать кэширование ответов LLM** для снижения стоимости повторных запросов

## Последствия

### Положительные

- Повышенная надежность системы AI-функций
- Снижен риск простоя из-за недоступности одного из провайдеров
- Возможность сравнения качества ответов от разных провайдеров
- Оптимизация стоимости через кэширование

### Отрицательные

- Увеличение сложности логики интеграции с LLM
- Потребность в поддержке нескольких API-интерфейсов
- Необходимость управления несколькими API-ключами

## Альтернативы

1. **Использование только одного провайдера** - высокий риск простоя при его недоступности
2. **Очередь провайдеров с ручным переключением** - требует вмешательства администратора при сбоях
3. **Отказ от AI-функций** - потеря ключевой особенности приложения

## Решение

Выбрана архитектура с двумя провайдерами и авто-fallback как обеспечивающая максимальную надежность и гибкость системы.
