## Техническое задание для AI‑агента: локальный запуск dev‑сервера (Vite)

### 1) Цель

Развернуть проект **Rutube Cinema Hub** локально и запустить **frontend** в режиме разработки через **Vite dev‑server**, чтобы приложение открывалось в браузере.

### 2) Порты (зафиксированное соглашение)

- **Приложение (frontend, dev): 9229**
- **Backend / API / Proxy (Express, `server/index.js`): 9230**
- **База данных (план): 9009**

Важно: dev‑сервер фронтенда можно запустить без бэкенда, но эндпоинты `/api/*` (proxy/logs/KinoRate AI) будут недоступны.

### 3) Требования к окружению

- Node.js: **18.19+ или 20+**
- npm

### 4) Ограничения и правила безопасности

- Не выполнять `git commit`, `git push`, `git rebase`.
- Не изменять зависимости «наугад» (версии в `package.json`) без явного запроса.
- Не публиковать и не печатать в логах секреты (включая `GEMINI_API_KEY`, `MISTRAL_API_KEY`).
- Допускается создание файла `.env.local` и установка `node_modules/`.

### 5) Пошаговый план выполнения (обязательный порядок)

#### Шаг 5.1 — Перейти в корень проекта

- `cd /home/asv-spb/Dev/my-coding/rutube-cinema-hub`

Критерий успеха: в папке есть `package.json` и `vite.config.ts`.

#### Шаг 5.2 — Проверить версии Node/npm

- `node -v`
- `npm -v`

Если Node ниже 18.19: остановиться и запросить у пользователя способ обновления (например, через nvm).

#### Шаг 5.3 — Установить зависимости

- `npm install`

Критерий успеха:

- команда завершилась без `npm ERR!`
- появился `node_modules/`

#### Шаг 5.4 (опционально) — Настроить KinoRate AI (Gemini/Mistral)

Если требуется функционал KinoRate AI (LLM, эндпоинты в `server/index.js`):

- создать `.env.local` в корне проекта
- добавить минимум:
  - `GEMINI_API_KEY=...`
- (опционально) настроить Mistral:
  - `MISTRAL_API_KEY=...`
  - `MISTRAL_MODEL_NAME=mistral-medium-2505`
  - `MISTRAL_ENABLED=true`
- (опционально) общие настройки:
  - `LLM_PROVIDER=auto`
  - `LLM_TIMEOUT_SEC=30`
  - `LLM_MAX_TOKENS=512`

Если ключей нет — dev‑сервер всё равно должен запускаться, но AI‑вызовы будут возвращать ошибки/пустые ответы.

#### Шаг 5.5 — Запустить backend (API/Proxy)

- `node server/index.js`

#### Шаг 5.6 — Запустить dev‑сервер

- `npm run dev`

Критерий успеха:

- Vite стартовал без ошибок
- в выводе есть URL `http://localhost:9229`

- `http://localhost:9229`

### 7) Типовые проблемы и правила реакции

#### 7.1 Ошибка `vite: not found`

Причина: зависимости не установлены.
Действие: выполнить `npm install` в корне проекта и повторить `npm run dev`.

#### 7.2 Порт 9229 занят

Действия (в порядке приоритета):

1. Показать, кем занят порт: `lsof -i :9229` (если доступно)
2. Без правок репозитория запустить на другом порту:
   - `npm run dev -- --port 9231`
3. Сообщить пользователю финальный URL.

#### 7.3 Rutube / CORS / прокси

Фронтенд сначала обращается к `/api/proxy?url=...`, а если локального прокси нет — использует публичные CORS‑прокси.
Это не должно блокировать запуск dev‑сервера.

---

### 8) Definition of Done (DoD)

Считается выполненным, когда:

1. `npm run dev` запущен и не завершается с ошибкой.
2. Приложение доступно по `http://localhost:9229` (или по согласованному альтернативному порту).
3. `curl -I` на соответствующий URL возвращает успешный статус.

### 9) Формат финального отчёта (обязателен)

- Node: x.y.z; npm: a.b.c
- Выполненные команды: `npm install`, `npm run dev` (и при необходимости `--port`)
- Итоговый URL: `http://localhost:9229` (или иной)
- Результат проверки: статус из `curl -I ...`
