# Документация безопасности прокси-сервера

## Обзор

В проекте Rutube Cinema Hub используется прокси-сервер для обхода CORS-ограничений и обеспечения доступа к данным Rutube из регионов с ограничениями. Данный документ описывает меры безопасности, применяемые к прокси-запросам.

## Текущая реализация безопасности

### 1. Валидация домена прокси-запросов

В `server.js` реализована проверка домена для предотвращения атак и несанкционированного использования прокси:

```javascript
// Проверка домена в server.js (строки 580-583)
if (!url.hostname.endsWith('rutube.ru')) {
  return res.status(400).json({ error: 'Invalid domain' });
}
```

### 2. Проверка протокола

Прокси-сервер принимает только HTTPS-запросы для обеспечения безопасности передачи данных:

```javascript
if (url.protocol !== 'https:') {
  return res.status(400).json({ error: 'Only HTTPS URLs are allowed' });
}
```

### 3. Ограничение длины URL

Для предотвращения атак с использованием чрезмерно длинных URL:

```javascript
if (targetUrl.length > 2048) {
  return res.status(400).json({ error: 'URL too long' });
}
```

## Планируемые улучшения безопасности

### 1. Расширение allowlist доменов

В будущем планируется расширить список разрешенных доменов для включения поддоменов Rutube:

- `*.rutube.ru`
- `rutube.ru`

### 2. Блокировка приватных IP-адресов

Для предотвращения SSRF-атак (Server-Side Request Forgery) планируется добавить проверку на приватные IP-адреса:

```javascript
// Псевдокод для проверки приватных IP
const isPrivateIP = (hostname) => {
  // Проверка на частные IP-адреса (10.x.x.x, 172.16.x.x-172.31.x.x, 192.168.x.x)
  // и другие зарезервированные диапазоны
};
```

### 3. Rate limiting

Для защиты от злоупотребления прокси-сервером планируется реализовать ограничение количества запросов:

```javascript
// Пример реализации с express-rate-limit
const rateLimit = require('express-rate-limit');

const proxyLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 минут
  max: 100, // Ограничение 100 запросов на IP за 15 минут
  message: 'Слишком много запросов к прокси',
  standardHeaders: true,
  legacyHeaders: false,
});
```

### 4. Валидация URL-параметров

Планируется добавить более строгую валидацию параметров URL для предотвращения внедрения вредоносных данных.

## CORS-политика

### Текущая политика

В настоящее время сервер использует CORS без ограничений (`cors()`), что представляет собой потенциальную угрозу безопасности.

### Планируемая политика

Необходимо ограничить origins списком разрешенных доменов:

```javascript
const cors = require('cors');

app.use(cors({
  origin: [
    'http://localhost:9229',  // Разработка
    'https://yourdomain.com',  // Продакшен
    // Другие доверенные домены
  ],
  credentials: true
}));
```

## Логирование и мониторинг

### Логирование прокси-запросов

Все прокси-запросы должны логироваться с указанием:

- Времени запроса
- IP-адреса клиента
- Целевого URL
- Результата запроса (успешно/ошибка)
- Причины ошибки (если применимо)

### Мониторинг аномалий

Планируется реализовать систему мониторинга для выявления:

- Подозрительной активности (подозрительно большое количество запросов)
- Попыток доступа к запрещенным доменам
- Аномальных паттернов использования

## Тестирование безопасности

### Тестирование валидации

Необходимо регулярно тестировать валидацию входных данных:

- Граничные значения длины URL
- Попытки доступа к запрещенным доменам
- Попытки обхода валидации

### Пентестинг

Периодически проводить тестирование на проникновение для выявления потенциальных уязвимостей.

## Рекомендации по безопасности

### 1. Регулярное обновление зависимостей

Следить за обновлениями используемых библиотек и своевременно применять патчи безопасности.

### 2. Использование Content Security Policy (CSP)

Добавить заголовки CSP для дополнительной защиты от XSS-атак.

### 3. Валидация и санитизация пользовательского ввода

Все пользовательские данные должны проходить валидацию и санитизацию перед использованием.

### 4. Использование HTTPS

Обязательно использовать HTTPS для всех соединений для защиты данных в пути.

## Заключение

Безопасность прокси-сервера является критически важной частью архитектуры приложения. Регулярный аудит, обновление политик безопасности и мониторинг аномалий помогут защитить приложение от потенциальных угроз.
